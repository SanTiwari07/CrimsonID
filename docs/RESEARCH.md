# Digital identity research

Reviewed on 27 November 2026 for the NFC-powered Sanskar Tiwari digital identity card.

## The visitor journey

The first screen has two jobs. It introduces Sanskar as an engineering student and AI systems builder, then gives the visitor a choice between exploring his work and saving his contact. Keep the authentic portrait, role, college, biography and strongest verified achievement close together. Place two primary actions immediately underneath. Give LinkedIn and email direct access in the same area.

After the introduction, group destinations by why a visitor would use them. A hiring manager can open the portfolio, résumé or LinkedIn. A hackathon judge can inspect selected projects, repositories and submissions. An engineering peer can look through projects, technical profiles and research. A visitor on a second phone can scan a QR code for the same page. A visible email address and a plain URL provide manual options when OS integration is unavailable.

## Interaction and compatibility

- **Tag and platform handling.** Encode a single NDEF URI record with the final HTTPS address. Apple documents background tag reading on iPhone XS and later and conditions that can temporarily suppress it. Android documents NDEF dispatch and notes that devices usually look for tags while unlocked and with NFC enabled. A standard URL uses the phone's OS to reach the browser and requires no Web NFC script. Pair it with QR and a readable URL. [NFC Forum specifications](https://nfc-forum.org/build/specifications/) · [Apple Core NFC](https://developer.apple.com/documentation/corenfc/adding-support-for-background-tag-reading) · [Android NFC basics](https://developer.android.com/develop/connectivity/nfc/nfc)
- **Contact exchange.** Serve a static UTF-8 contact file with a structured family and given name, display name, job description, work email and portfolio URL. Use CRLF line endings and correct property escaping. RFC 6350 defines the current vCard 4.0 format. If selecting 3.0 for broader importer compatibility, validate the generated file against RFC 2426 and document why. On a phone, the browser may open a contact preview or save a file for import. The acceptance test is whether the name, email and URL reach Contacts. [RFC 6350](https://datatracker.ietf.org/doc/html/rfc6350) · [RFC 2426](https://datatracker.ietf.org/doc/html/rfc2426)
- **Sharing.** The share action can call `navigator.share` from a direct tap where available. A cancelled share should return to the page. A separate Copy Link action should also expose a selectable URL when clipboard access is denied. Use the same mechanism for the visible email address. [W3C Web Share API](https://www.w3.org/TR/web-share/) · [W3C Clipboard API](https://www.w3.org/TR/clipboard-apis/)
- **QR.** Generate SVG or PNG locally during the build using the exact canonical HTTPS address used for NFC. Use dark modules on white, retain a four-module clear margin and preserve square geometry. An automated decoder should recover the exact payload from the generated file. Check the QR on-screen and printed with physical cameras before distributing it. [DENSO WAVE QR code area guidance](https://www.qrcode.com/en/howto/code.html)
- **Readability and accessibility.** Start with mobile reading order, 16px body copy and 48px preferred touch targets. Keep strong focus indicators, preserve 4.5:1 normal-text contrast and allow larger browser type, zoom, wrapping and reduced motion. Treat touch targets as independent controls with useful labels and use a live status message for copy feedback. [WCAG 2.2](https://www.w3.org/TR/WCAG22/) · [Apple Human Interface Guidelines](https://developer.apple.com/design/human-interface-guidelines/)

## Implementation recommendations

1. Emit complete semantic HTML from one profile data file. Core links, the email address and downloadable contact stay available without JavaScript. Use a small script for sharing and clipboard enhancements.
2. Put the portrait, short professional introduction, a documented achievement and the two main actions first. Place three or fewer selected projects before or alongside the grouped technical and social links, as space permits.
3. Set a small first-load asset budget. Keep the portrait at its display scale, set explicit image dimensions, use lazy loading for below-the-fold media, and use a local font or system fallback. Self-host the necessary assets and measure with realistic mobile throttling.
4. Keep personal identity, profile details, published projects and professional links independent of brittle third-party images, widgets or account integrations. Confirm ambiguous claims with owner or organizer evidence.
5. Use no analytics by default. If aggregate visit counts become useful, compare self-hosted summary logs with providers that describe cookieless modes. They still involve a data collection and retention decision. [Plausible data policy](https://plausible.io/data-policy) · [Cloudflare Web Analytics](https://www.cloudflare.com/web-analytics/)
